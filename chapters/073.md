# 073｜另一邊也有它

第二十一天上午九點十四分，通知先到了歷史完整性審查官那裡。

林澈是九點二十七分才被叫進三樓協調室。

不是人物案件。

至少一開始不是。

中央畫面上只有一張資產釋放單。

【南區雨水調節站 R-12／舊控制閘道】

【狀態：已退役／等待實體資產釋放】

【既有有限狀態保全：有效】

【目的：確認保全摘要足以取代實機保留，允許後續普通電子資產處理】

林澈站在門邊看了幾秒。

R-12 是十三天前換掉的。

那晚舊閘道沒有因歷史不一致被升格成案件證物，只在切換前留下九十天的有限狀態保全：lineage 摘要、政策索引、硬體序號和當代驗收狀態。

新控制器則從二一八七年乾淨重新註冊。

城市照常排水。

舊機器現在只是等著離開資產系統。

「為什麼叫我？」林澈問。

歷史完整性審查官沒有把椅子推給他。

「不是讓你查。」

她把釋放單往下滑。

「資產中心在銷毀實機前，要確認我們留下的摘要未來真的還能被獨立重驗。你當時是技術陳述人，所以只需要確認：今天讀的確實是那晚封存的四個欄位，不是後來另外拼的。」

林澈點頭。

這個問題很窄。

他能回答。

硬體序號一致。

封存雜湊一致。

當代驗收狀態一致。

lineage 摘要的根指向也一致。

「是那晚的。」他說。

審查官在旁邊簽下：

【技術陳述確認：封存狀態同一】

到這裡，本來就可以結束。

但資產釋放系統還有最後一項。

【若實機銷毀，lineage 摘要之來源指向是否仍可驗？】

狀態停在：

【待解析】

維運工程師從遠端說：「這不是你們案件查詢，是資產釋放的固定欄。舊機器沒了以後，不能只剩一串沒人知道從哪來的摘要。」

審查官說：「只解析摘要自己的上游見證。不要展開政策內容。」

「使用者？」

「不讀。」

「操作紀錄？」

「不讀。」

「其他四百多個節點？」

「不碰。」

遠端工程師送出解析。

畫面先回來一個很普通的結果。

【現行封存來源：R-12 舊控制閘道／切換前唯讀狀態】

下一層是二一八七之前的業務系統。

再往上一層，日期跳到二一六四。

林澈沒有立刻看懂。

那不是內容。

只是一張 migration receipt 的表頭。

【2164 市政資料整併／lineage state migration】

【接收：現役舊系統維運體系之前身】

【移交見證：有效】

【移交服務：市政連續性服務】

房間裡沒有人說話。

林澈第一個念頭不是 R-12。

是三份二一六二來源上那個已退役的保存策略所有者。

同樣六個字。

市政連續性服務。

他沒有自己把兩邊接起來。

甚至沒有把人物案件叫出來。

歷史完整性審查官先問遠端工程師：「這個欄位是名稱描述，還是 receipt 的簽發主體？」

對方停了幾秒。

「簽發主體。」

「可驗嗎？」

「可以。receipt 的簽章鏈在封存摘要裡。」

「現在驗。」

解析器回傳：

【2164 migration receipt：簽章有效】

【簽發主體：市政連續性服務】

【作用：證明 legacy policy state 於 2164 整併時完成跨業務交接】

【不證明：交接前 lineage 內容正確】

最後一行很重要。

它沒有替二一五八和二一六零的矛盾作答。

沒有讓那把兩年後才生成的公鑰突然合理地出現在更早的原始封存 payload 裡。

這張 receipt 只能證明：到了二一六四，某一份 legacy policy state 被一個叫「市政連續性服務」的系統見證著，交給後來的業務體系。

維運工程師鬆了一口氣。

「那實機可以放掉了？」

審查官沒有回答他。

她看向林澈。

「你以前在哪裡看過這個名字？」

林澈知道她不是在考他。

「人物支線的三份來源。」

「哪一層？」

「長期保存策略所有者。」

「你有權把那三份來源打開嗎？」

「沒有。」

「我也沒有要你打開。」

她轉向案件承辦端。

「只做既有結論層級的 metadata 對照。確認是不是同一個制度名稱，不讀人物內容。」

人物案件沒有因此重新啟動搜尋。

沒有臉。

沒有交通。

沒有姓名。

只有一條已經存在的來源層備註被讀回來：

【legacy preservation concept：市政連續性服務／持續可驗證保存】

【目前作用：解釋長期可重驗性；不作人物身份加權】

兩個視窗第一次同時出現在中央畫面。

左邊是 R-12。

右邊是三份二一六二來源的來源層備註。

不是同一個案件。

不是同一種資料。

甚至不是同一個原始目的。

一邊是舊控制閘道的政策 lineage。

另一邊是工程、媒介與軌道事故的未來可重驗保存。

共同的只有那個已退役服務。

審查官沒有讓畫面停太久。

她先把限制寫上去。

【不得推論：R-12 與 H-2162-U01 有人物／事件關聯】

【不得推論：市政連續性服務造成 2158／2160 歷史不一致】

【不得推論：共同服務名稱＝共同來源內容／共同隱藏系統】

【可建立：兩條獨立支線存在同一可驗制度節點】

林澈盯著最後一行。

這和之前不一樣。

以前「市政連續性服務」只是回答一個很局部的問題。

為什麼三份二十五年前的來源還能被重新驗證。

現在它也出現在另一件完全不同的事上。

不是影像。

不是人物。

不是事故。

而是一條已經因二一五八／二一六零矛盾而失去自動可信性的歷史 policy lineage。

主管從旁邊說：「所以它以前管很多東西。」

「至少不只媒體保存。」審查官說。

「那可以查完整索引了？」

她沒有立刻回答。

林澈也沒有說想查。

審查官把 R-12 的 migration receipt 再往下展開一層。

只有一個尚未解析的來源端欄位。

【source-side continuity reference：存在】

【內容：未讀】

「現在有具體問題了。」她說。

沒有人問「那個服務到底是什麼」。

那太大。

真正的問題只有一個。

R-12 在二一六四被交給後來業務體系時，這張 migration receipt 是根據哪一個 source-side continuity reference，替它的舊 lineage 做交接見證？

如果那個 reference 只是正常的舊設備狀態，事情仍然可以很普通。

如果它指回一張 Chapter 043 所說的正常 continuity receipt，也許能進一步釐清哪一段 lineage 從何時起可以被後來系統背書。

如果它什麼也回答不了，至少也不會因為「市政連續性服務」這個名字聽起來神祕，就把整個索引翻開。

審查官把下一步寫成：

【候選：R-12／2164 migration receipt／source-side continuity reference 有限解析】

【目的：確認指定 disputed lineage 於 2164 移交時所依據之直接來源見證】

【不包含：人物資料／其他節點／完整市政連續性服務索引】

【狀態：待獨立必要性覆核】

人物案件沒有因此變成 active query。

但案件架構多了一條此前不存在的關係。

【跨支線共同制度節點：市政連續性服務／已建立】

【含義：未定】

林澈看著這兩行。

十三天前，R-12 從今天開始。

他那時以為那台機器最大的意義，是一段無法背書的歷史第一次改變了當代要怎麼做。

現在舊閘道即將真的離開城市資產系統，卻在離開前留下另一件事。

那段歷史不是孤零零地斷在二一五八和二一六零之間。

至少到二一六四，有一個系統曾經接過它。

而那個系統，也曾經接過三份留下陌生人身影的來源。

這還不是答案。

卻第一次讓林澈不能再把「歷史出了什麼問題」和「那個人為什麼會留下」當成完全沒有交點的兩件事。

十點零八分，資產中心再次問：

【R-12 舊控制閘道／是否允許實體資產釋放？】

歷史完整性審查官看完封存摘要。

「允許。」

她簽下去。

【實機保留：不再必要】

【既有有限狀態保全：維持原九十天】

【新成立制度關係：由封存摘要獨立保存，不依賴實機】

維運工程師說了一句「收到」，遠端視窗就關了。

沒有任何人要求把舊閘道留下來當神祕證物。

它下午就會進普通電子資產流程。

林澈站起來時，中央畫面還剩兩個名字。

R-12。

市政連續性服務。

人物支線那個視窗已經關掉了。

主管問：「所以今天算案件重新啟動？」

審查官搖頭。

「不是人物搜尋重新啟動。」

她把共同制度節點那一行固定到跨支線關係層。

「是我們第一次有理由承認，兩個原本分開保管的問題，碰到了同一個真的東西。」

林澈沒有回答。

他看著那個已經被固定的制度節點。

這一次，他沒有想知道下一扇門後面有什麼。

他只知道，門第一次真的有了鉸鏈。
