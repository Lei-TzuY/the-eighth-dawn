# 075｜只能證到這裡

第二十二天上午九點十七分，林澈沒有進三樓。

這是昨天就決定好的。

`source-side continuity reference` 的讀取由歷史完整性審查端執行，雙人見證，範圍只到 target identifier、object class、保存來源和最小驗證鏈。

他能做的事只有等正式結果。

九點二十分，他在第六修復室重新打開一份舊地下風道的振動紀錄。

主管從旁邊看他一眼。

「今天這張圖你打算盯幾次？」

林澈沒有笑。

「一次。」

「有進步。」

風道紀錄的問題很普通。

一枚維修機器人在穿過檢修井時撞到側壁，讓三秒鐘的加速度資料整段飽和。林澈把飽和區標成不可恢復，不替它補出一條漂亮曲線，再把前後仍可信的訊號接回來。

九點三十八分，工作牆右側亮起一條灰色通知。

不是案件警報。

【R-12／2164 migration receipt】

【single-reference resolution：完成】

【結果傳送：技術陳述層】

林澈把手從控制板上移開。

主管沒有靠過來。

她只說：「看吧。」

正式結果只有半頁。

最上面是昨天核准的那一格。

【reference target identifier：R12-PRE-MIGRATION-LINEAGE-CHECKPOINT／2163-Q4】

【object class：legacy lineage state checkpoint】

【payload：未讀／不在核准範圍】

下面是來源。

【形成來源：原業務維運域】

【保存見證：市政連續性服務】

【最早可獨立驗證形成：2163／第四季】

【驗證鏈：有效】

林澈停在最後一行。

沒有新服務名稱。

沒有新人物。

沒有任何一段隱藏內容被翻出來。

歷史完整性審查官的內線在幾秒後接進來。

她身後仍是昨天那個範圍覆核員。

「先說不能證明什麼。」她說。

林澈點頭。

中央畫面只放四個年份。

二一五八。

二一六零。

二一六三。

二一六四。

那張 migration receipt 能被證明在二一六四真的存在。

現在又能證明，它不是憑空宣告一段 lineage 已經可接手，而是引用了一個二一六三第四季已形成、且有獨立驗證鏈的 lineage state checkpoint。

可 checkpoint 的 payload 沒有被讀。

也沒有必要讀。

因為今天核准的問題不是「二一六三裡面寫了什麼」。

而是「二一六四的交接到底依據哪一個直接來源見證」。

答案已經出來了。

一個前一季形成的 lineage state checkpoint。

「所以現在能往前證到二一六三？」主管問。

審查官說：「精確一點。」

她把結果寫成：

【R-12 legacy lineage／可重驗區段：2163-Q4 checkpoint → 2164 migration receipt／成立】

【2163-Q4 以前之 lineage correctness：不由本 reference 背書】

【2158／2160 歷史時間不一致：維持】

主管讀完，皺了皺眉。

「就這樣？」

「就這樣。」

她看向林澈。

「失望嗎？」

林澈想了一下。

「有一點。」

主管側頭看他。

「昨天不是還說普通答案也可以？」

「普通答案可以，失望也可以。」

主管笑了一聲。

歷史完整性審查官沒有笑。

她把 target 的最小 provenance 再拉開一層，但沒有碰 payload。

那個 checkpoint 不是由「市政連續性服務」產生內容。

形成來源仍是原本負責 R-12 舊 policy state 的業務維運域。

市政連續性服務做的是另一件事。

它替那個 checkpoint 留下可重驗的保存見證，然後在二一六四整併時，讓 migration receipt 可以指回去。

「換句話說，」審查官說，「目前沒有證據說它替 R-12 創造了那段歷史。」

「它只是接手？」主管問。

「至少在這裡，是見證接手。」

林澈看著那兩行。

形成來源。

保存見證。

同一個物件，兩種責任。

這和三份二一六二來源突然有了一點更具體的共同語法。

不是內容相同。

也不是事件相同。

而是某個系統在原業務之後出現，留下足以讓未來的人知道：這個東西從哪裡被接過來、當時哪一段狀態可以被重驗。

「那三份人物來源也是這樣？」主管問。

審查官立刻搖頭。

「不能倒推。」

她把人物支線保持關閉。

「我們只知道三份來源的長期保存策略所有者是同一服務，而且那個策略保留來源形成、交接與獨立見證所需的最小證據。今天這個結果讓兩邊的 operational behavior 更相容，但不證明是同一套內部流程，更不證明人物來源也有這種 checkpoint。」

林澈說：「所以 bridge 變得比較普通了。」

審查官看他。

「也比較真。」

這句話讓房間安靜了一下。

如果「市政連續性服務」今天回傳的是一個誰都沒見過的黑盒識別碼，事情會更像一個祕密。

現在不是。

它做的事情甚至可以被正常制度語言描述。

原業務形成狀態。

它保存見證。

整併時再把可重驗的那一段交出去。

可這並沒有讓最早的矛盾消失。

二一六三的 checkpoint 可以是真的。

二一六四的 migration receipt 也可以是真的。

它們甚至可以彼此完美一致。

仍然沒有人能因此回答：為什麼二一五八的原始封存 payload 裡，會有一把直到二一六零才第一次生成的公鑰。

歷史完整性審查官把正式狀態改得更窄。

【歷史信任狀態：未解】

【已可驗 lineage boundary：2163-Q4 起】

【pre-boundary history：不由後續 continuity witness 回填】

林澈看著「boundary」那個字。

之前他們只有一整段不能簽名的歷史。

現在不是全部都黑著。

至少從二一六三第四季開始，後面的交接可以被重新走一遍。

真正不能被後來制度替它說話的，只剩更前面。

那沒有把問題變小到安全。

反而把它切得更乾淨。

十點零六分，範圍覆核員問：「需要讀 checkpoint payload 嗎？」

審查官沒有立刻回答。

她先看今天原本的目的。

直接來源見證是什麼？

已回答。

指向能不能驗？

能。

這個見證能把 lineage 背書到哪裡？

到二一六三第四季形成的 checkpoint 為止。

再往前，沒有新問題。

至少今天沒有。

「不讀。」她說。

畫面隨即加上一行：

【target payload：保持關閉】

【後續擴張必要性：未建立】

林澈沒有要求保留窗口。

也沒有問完整市政連續性服務索引裡是不是還有更早的東西。

因為現在他們已經知道，後來的見證可以非常誠實，仍然救不了更早的歷史。

十點十二分，內線結束。

主管看著他。

「所以那個服務不是答案。」

林澈把風道振動紀錄重新叫回來。

「至少不是這個答案。」

「那它是什麼？」

他沒有立刻說。

幾秒後，他把那三秒鐘不可恢復的飽和區重新標了一次。

前面的訊號可信。

後面的訊號也可信。

中間那三秒，仍然不能補。

「它比較像有人從某一點開始，願意替後面的東西負責。」

主管看向他。

林澈補了一句。

「不是替前面發生過什麼負責。」

十一點前，他把風道修復送出。

R-12 的歷史狀態也被重新固定。

不是從二一五八一路可信到今天。

也不是整段全部失效。

而是第一次有了一條可以明確畫出的線。

線後面的交接，能驗。

線前面的矛盾，仍在。

人物案件沒有因此重新啟動。

H-2162-U01 的名字仍然不存在。

林澈自己的二一八七人生也沒有少掉任何一頁。

兩件事仍然沒有被放進同一個解釋裡。

只是那個共同制度節點的形狀，比昨天清楚了一點。

它不像一扇藏著所有答案的門。

更像一道很誠實的界線。

它只肯證明自己真正見過的那一邊。
