# 086｜明天九點半

第二十七日上午，林澈被派到地下二層整理一批防潮庫的舊紙本移交紀錄。

不是因為那裡出了問題。

只是昨晚空調維護時，有一排濕度感測器短暫離線，備援庫因此啟動了人工抽查。電子索引仍在，紙本也沒有受潮；需要做的只是確認兩邊數量、封條與抽樣頁碼一致。

較資淺的修復員蹲在另一端，把一疊灰色封套按年份排開。

「這裡真的有人喜歡紙。」

林澈沒有抬頭。

「紙不會自己改欄位格式。」

「紙會發霉。」

「所以我們現在在地下二層。」

她想了一下。

「有道理。」

兩人繼續工作。

九點十五分，林澈的終端沒有案件通知。

九點四十七分，沒有。

十點二十三分，還是沒有。

他沒有主動打開歷史連續性問題頁。

昨天那張 2164 consolidation-exchange receipt 已經把問題往前推了一層。predecessor relation pointer 確實存在，但 scope review 還沒完成。

那不是一個需要他刷新頁面的流程。

十一點零六分，他們對到最後一只封套。

紙本編號和電子索引差一位。

較資淺的修復員立刻皺眉。

「漏掃？」

林澈先看封條。

「不是。」

他把旁邊的移交表抽出來。

十六年前，備援庫換過一次貨架編碼。電子索引用了新架號，紙本封面保留舊架號；真正的 object id 一致。

「兩邊都對。」他說。

「只是名字不同？」

「架號不同，物件一樣。」

「所以改哪邊？」

「都不要改。補 mapping。」

她把對照寫進抽查表。

「今天一直在做這種事。」

「哪種？」

「看起來矛盾，最後只是交接。」

林澈把封套放回盒裡。

「不要因為今天碰到普通交接，就預設所有 carry-forward 都普通。」

她看他一眼。

「你又想到自己的事。」

「我是在提醒妳不要想到我的事。」

「差很多嗎？」

「差很多。」

她笑了一聲。

十一點四十二分，兩人推著空推車回到電梯口。

門打開時，主管站在裡面。

她手上沒有灰色封套。

只有平常的工作板。

「剛好。」她說。

林澈走進去。

電梯往上。

主管先看較資淺的修復員。

「防潮庫？」

「完成。沒有受潮，只有舊架號 mapping。」

「送普通紀錄。」

「好。」

她在三樓先下去。

電梯門重新關上。

只剩主管和林澈。

主管才說：「scope review 定案了。」

林澈看著樓層數字往上跳。

「核准？」

「核准一部分。」

「哪一部分？」

「只准解析那一個 predecessor pointer。」

林澈沒有問第二個問題。

主管接著說：「不是開完整 predecessor archive。也不是沿著它往前找。只允許把 pointer 指向的 relation object 取回，驗證它自己的 object class、形成時間邊界、source domain、relation semantics，還有形成時直接附著的 evidence-class summary。」

「內容 payload？」

「如果不需要，不讀。」

「如果需要？」

「停。」

電梯在五樓停了一下，沒有人進來。

主管說：「核准書寫得很清楚。只要 interpretation 必須跨進人物姓名、影像、家庭資料、其他 subject links，或需要 sibling reference 才能成立，就回報 `INSUFFICIENT WITHIN CURRENT SCOPE`。不能因為 pointer 已經開了，就順手把下一扇門也打開。」

林澈點頭。

「理由呢？」

「這個 historical-continuity 問題已經無法靠 2164 receipt 自己回答。」

「因為 receipt 只知道 carry-forward。」

「對。要判斷那個 pre-consolidation assertion 到底只是普通 lineage carryover、high-recall relation，還是別的 relation class，至少得知道它自己是什麼。」

電梯到了六樓。

門打開。

主管沒有立刻出去。

「但不是今天。」

林澈站在門邊。

「什麼時候？」

「明天九點半。」

這是她第一次給出一個時間。

不是 vague 的「等獨立端」。

不是「之後有結果會通知」。

是一個具體的九點半。

林澈問：「誰在場？」

主管走出去。

「歷史完整性審查端兩人，加一名來源驗證員。」

「妳呢？」

「不在。」

「我呢？」

主管停下來看他。

林澈自己先說：「也不在。」

「對。」

他沒有意外。

可知道「不參與」和知道「明天九點半，有三個人會在另一個房間打開那一個 pointer」仍然是兩件不同的事。

前者是一條規則。

後者有時間、有房間、有會發生的動作。

主管把一張正式範圍摘要傳到他的只讀收件匣。

只有六行。

【approved object：single cryptographically bound predecessor relation pointer】

【purpose：determine relation object class／formation boundary／source domain／relation semantics／direct evidence-class summary】

【sibling traversal：prohibited】

【person-identifying payload expansion：prohibited】

【affected-person live participation：no】

【finalized relevant result notification：retain】

林澈看完。

「所以明天如果他們打開之後，只看到『還需要別的東西才能知道』——」

「那就停在那句話。」

「不會為了已經花時間做到這裡，再補一個授權？」

「不會因為花了時間。」

主管說。

「如果有新的必要性，重新判斷。沒有就停。」

林澈把摘要關掉。

這答案很普通。

甚至讓人有點討厭。

他花了二十六天才走到一個真正存在的 predecessor pointer；等到那扇門終於被允許打開，第一件被寫進核准書的事，仍然是什麼情況下必須停手。

可他也知道，如果沒有那一行，前面那些界線就都只是裝飾。

---

午休後，主管排明天上午的工作。

九點半那一格，林澈沒有任何案件行程。

他本來也不該有。

主管問：「明天九點到十一點，河東舊防洪牆的裂縫影像要做來源整理。要不要排你？」

林澈看著工作板。

九點半。

另一個房間。

一個比二一六四更早的 relation object。

然後是河東防洪牆，十二年前的影像，三十七處裂縫標記，兩批施工相機。

「排我。」他說。

主管看他一秒。

「確定？」

「我留在桌前也看不到 live result。」

「可以請普通工作延後。」

「為什麼？」

主管沒有回答。

林澈自己笑了一下。

「對，沒有為什麼。」

她把他的名字放進防洪牆來源整理。

不是為了讓他忘記。

也不是因為那個 pointer 不重要。

只是明天九點半，既然真正需要在場的人不是他，他就不必把自己的上午空成一個等待室。

下午四點，較資淺的修復員經過他桌邊，看見明天排程。

「你明天九點半不是有事？」

林澈抬頭。

「妳怎麼知道？」

「主管剛才問來源驗證員調班，我猜的。」

「那不是我的會議。」

她站住。

「可是是你的事。」

林澈想了想。

「會碰到我。」

「這不就一樣？」

「不一樣。」

她露出那種等他把話講成人話的表情。

林澈指了指明天的防洪牆工作。

「有人要驗一份跟我有關的舊關係。我沒有資格幫他們決定它代表什麼。」

「所以你去看裂縫？」

「所以我去做我的工作。」

她看了兩秒。

「你明天會一直看時間。」

「可能。」

「那你還是會等。」

林澈沒有否認。

「等跟守在門口不一樣。」

這次她沒有笑他。

---

傍晚離開前，林澈把明天的防洪牆資料包先下載到普通工作區。

來源鏈很完整。

兩批施工相機都有交接紀錄。

沒有任何一項與人物案件、predecessor pointer 或市政連續性服務有關。

他確認完畢，關掉工作首頁。

沒有把九點半設成私人提醒。

也沒有把 scope review 摘要釘到最上層。

真正的排程已經存在於該存在的地方。

明天九點半，那一個 predecessor pointer 會被獨立解析。

可能得到一個普通答案。

可能只得到「目前範圍不足」。

也可能讓問題再往前移一次。

他不知道。

第一次，未知不只是一個沒有日期的遠處。

它有了明天九點半。

而那個時間，不需要他在門口。
