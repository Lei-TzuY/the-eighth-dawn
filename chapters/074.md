# 074｜只開這一格

第二十一天下午一點四十七分，林澈回到第六修復室。

上午那個名字沒有跟著他回來。

至少工作牆上沒有。

他面前是一份十九年前的地下排水泵巡檢紀錄，影像左下角有一段鹽霧造成的色偏。原始校正板還在，修復不難。他把第一輪色彩反推跑完，停在結果頁，看了十幾秒才發現自己根本沒在看數值。

主管從另一張桌子後面說：「你已經第三次盯同一張校正圖。」

林澈把視線拉回來。

「有嗎？」

「有。」

「那妳怎麼不早點講？」

「前兩次我以為你在思考。」

「第三次呢？」

「確定你只是在發呆。」

林澈把修復流程重新拉到前景。

上午離開三樓協調室時，他沒有要求打開任何東西。

歷史完整性審查官也沒有。

那個 `source-side continuity reference` 仍然只是一個存在、但未讀的欄位。

可它和以前那些「也許某處還有資料」不一樣。

它就在已驗證的 migration receipt 裡。

不是猜測。

不是新搜尋。

是已經知道有一個指向，只是不知道它指向什麼。

主管問：「你覺得他們會核准嗎？」

林澈沒有問她說的是什麼。

「不知道。」

「你想核准？」

他把地下泵的校正板縮小。

「想知道，不等於該核准。」

主管看了他一眼。

「最近很會答。」

「這次是真的不知道。」

他停了一下。

「如果只是因為上午看見同一個服務名稱，就說整個舊索引都應該打開，那跟以前沒有證據時一直想找下一個東西也差不多。」

「那只開那個 reference？」

「也不能因為它比較小就自動合理。」

主管笑了一聲。

「很好。你現在連小門都不敢進。」

「不是不敢。」

林澈重新送出色彩反推。

「是先要有人說清楚，為什麼這扇門真的通往我們現在問的問題。」

下午兩點十九分，工作牆右側亮起一個沒有案件內容的通知。

【資料用途／必要性獨立覆核】

【對象：R-12／2164 migration receipt／source-side continuity reference】

【狀態：進行中】

【受影響人物資料：無】

林澈沒有被叫去三樓。

過了兩分鐘，歷史完整性審查官的內線接進第六修復室。

畫面裡只有她，和一名林澈沒見過的範圍覆核員。

對方沒有調出人物案件。

桌面上甚至沒有 H-2162-U01 這個代號。

只有三樣東西。

R-12 的 2187 有限狀態保全摘要。

上午驗過的 2164 migration receipt。

以及那一格仍標著未讀的 reference。

範圍覆核員先說：「我只看必要性，不判斷歷史內容。」

審查官點頭。

「可以。」

「問題是什麼？」

「二一六四交接時，簽發 migration receipt 的服務，根據哪一個直接來源見證，認定這份 legacy policy state 可以被移交給後續業務體系。」

「為什麼現在需要知道？」

審查官沒有說「因為它很可疑」。

也沒有提人物支線。

她把二一五八與二一六零的既有正式狀態放在畫面最左側，只留結論。

【歷史信任狀態：未解】

【2164 migration：已證明發生】

【pre-handoff lineage correctness：未證】

「因為現在只知道二一六四有人接手。」她說，「不知道交接見證當時依據的是哪一段來源證據。這會決定我們能把可驗 lineage 往前背書到哪裡。」

範圍覆核員問：「完整的市政連續性服務索引能回答嗎？」

「可能能。」

「那為什麼不開？」

審查官指向那一格 reference。

「因為 receipt 自己已經留下直接指向。」

「如果這個指向失效？」

「再重新評估。」

「如果它只是一個一般政策狀態物件？」

「那就是答案。」

「如果它什麼也證明不了？」

「也是答案。」

範圍覆核員往後靠了一點。

「人物支線那個共同服務節點呢？」

林澈第一次抬頭。

審查官卻沒有看他。

「不是這次存取的必要性來源。」

「可是如果沒有那個共同節點，你們會現在問這個欄位嗎？」

房間安靜了一下。

這個問題比前面幾個更難。

審查官最後說：「上午的共同節點讓我們知道這個服務不只出現在一條資料鏈上，所以它提高了這個欄位的制度意義。」

她停了一下。

「但如果要讀這一格，理由仍然必須只靠 R-12 自己成立。」

範圍覆核員說：「再講一次，只講 R-12。」

審查官照做。

二一五八原始封存裡有一把兩年後才生成的公鑰。

二一六四的 migration receipt 只證明後來有人把既有 policy state 接過去。

如果要判斷二一六四當時究竟替哪一段舊 lineage 背書，最直接的問題不是「市政連續性服務還做過什麼」，而是那張 receipt 自己宣告依據了什麼來源見證。

reference 已存在於 receipt。

不需要搜尋其他節點。

不需要打開人員資料。

不需要展開完整制度索引。

甚至不需要先知道那個來源見證的內容。

第一步只需要解析它指向哪一個物件，以及那個指向本身能不能被驗證。

範圍覆核員看向林澈。

「你是 R-12 那晚的技術陳述人？」

「是。」

「你能證明這個 reference 欄位是那晚封存 lineage 摘要的一部分嗎？」

林澈沒有碰查詢。

他只打開自己可以看的封存結構說明。

那一格在上午已確認的根摘要裡。

內容被標成未解析參照，但位置、長度與 digest 都在切換前唯讀封存中。

「能。」他說，「可以證明欄位和 digest 當時就存在。不能證明它指向的內容是什麼，因為還沒讀。」

「如果核准，誰讀？」

「不是我。」

範圍覆核員點了一下頭。

這個回答沒有替他加分。

只是把角色放回原來的位置。

兩點四十六分，覆核結果出來。

沒有綠燈灑滿整張畫面。

只有一條很窄的授權。

【必要性：成立】

【核准：source-side continuity reference／單一參照解析】

【可讀：reference target identifier、object class、保存來源、驗證鏈最小 metadata】

【不得讀：target 內容 payload／其他 sibling references／服務完整索引／其他節點／人物與使用者資料】

【目的限制：只回答 R-12 2164 migration receipt 所依據之直接來源見證】

下面還有兩行。

【人物支線共同制度節點：不得作本次擴張依據】

【解析結果不得自動觸發人物資料搜尋】

主管讀完，低聲說：「所以門開了。」

林澈看著那個授權範圍。

「只開一格。」

範圍覆核員說：「而且今天不一定要讀。」

審查官問：「為什麼？」

「因為必要性覆核的工作是決定能不能，不是替你製造緊迫性。」

她看了一眼時間。

「R-12 實機已經可以正常釋放，封存摘要也沒有到期。沒有證據正在消失。」

這句話讓林澈停了一下。

第一晚，如果有人在他面前說「沒有證據正在消失」，他可能會覺得那只是還沒來得及看見危險。

現在他反而知道，沒有緊迫性也是一種資訊。

它表示他們不必把剛得到的合法權限立刻用掉。

審查官最後把讀取排到隔日上午。

不是等待更多權限。

只是讓今天的範圍決定和明天的證據讀取分開。

【執行窗口：第二十二日上午】

【執行者：歷史完整性審查端／雙人見證】

【林澈：技術陳述人／只接收核准結果】

人物案件仍然沒有 active query。

完整的市政連續性服務索引仍然是關著的。

下午三點零二分，內線結束。

林澈回到地下排水泵的巡檢紀錄。

那段色偏已經修好了。

他把校正板和輸出影像並排看了一次，確認沒有把鹽霧的原始偏色也一起「修正」掉，然後送出。

工作牆右側還留著明天的執行窗口。

一個 reference。

一個 target identifier。

一條最小驗證鏈。

就這些。

上午，他第一次看見兩個問題碰到同一個制度節點。

下午，制度沒有因為那個發現變得興奮。

它反而先決定，明天只能看多小的一塊。

林澈盯著那個窄得幾乎不像進展的範圍，忽然覺得這比直接把整扇門推開更讓人不安。

因為如果那一格裡真的有東西，明天他們就不能再說，是自己翻得太遠才碰見的。
